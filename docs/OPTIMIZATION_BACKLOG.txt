- 所有收益都是**静态估算**，必须 A/B：
  · F3 面板取 3 次中位数（不是单次读数）；

三、P1：低风险、收益明确（**已完成 2026-11-12**）
--------------------------------------------------------------------------------
[x] P1-1 = B1  色差复用：GradeScene x3 -> 拆 GradeCtx                     [a545ab49]
    位置：shaders/program/post/Final.frag（CHROMATIC_ABERRATION 段）
    现状：R/G/B 三个通道各调一次 GradeScene，而它内部要算泛光/体积雾/雨/暗角/曝光
    做法：抽 GradeCtx（这些项各算一次），三通道只做采样+通道选择
    收益：0.2–0.3 ms/帧  ←剩余最划算的一项
    风险：低（纯重构；要求输出与改前逐位一致）
    验证：F3 中位数 + 改前/改后同机位截图逐像素对比（应无差异）

[x] P1-2 = B3  PCF 的 shadowtex0 / shadowtex1 判据不自洽              [4f427c3a]
    位置：shaders/lib/lighting/shadow/Render.glsl（CalculatePCSS / 半影采样）
    现状：shadowtex0 用 texelFetch 点采样、shadowtex1 用硬件双线性，两者用 != 比较，
          半影像素会被误判成「透明遮挡」，于是走彩色分支，用遮挡物 albedo 给半影染色/压暗
    做法：两者统一（都用点采样，或都用双线性）
    收益：0.01–0.04 ms/帧 + 修掉半影被染色/压暗的观感问题
    风险：低；改完专门看树叶/栅栏投下的半影颜色
    验证：半影近景截图 + F3

[x] P1-3 = B7  云影正交范围 *32 -> *8                                  [5c64658c]
    位置：云影生成（GenCloudShadow / 云影投影矩阵）
    现状：把 2048 格压进 512²，约 4 格/纹素，97% 的纹素根本采样不到
    做法：范围收 4 倍（*32 -> *8），同成本
    收益：性能≈0，白送 4x 云影锐度（纯画质）
    风险：零（但要确认远处云影边缘没有硬切）
    验证：抬头看云影边缘清晰度对比

[x] P1-4 = B9  SkyView 全屏 dispatch 服务 192x192 的 LUT              [0865d879]
    位置：shaders/program/atmosphere/SkyView.comp（workGroupsRender）+ 调用处
    现状：全屏 dispatch，每个线程进来先做 SSBO 判据才决定要不要算（163x 超额线程）
    做法：dispatch 收到 LUT 尺寸（如 192/8 组）
    收益：几十 µs/帧
    风险：低，但**改前必须先抓帧确认 LUT 非空**（本仓有「改了之后 LUT 全黑」的前科）
    验证：RenderDoc 看输出纹理内容 + 天空外观

[x] P1-5 = G1  GAMMA_CORRECTION 滑条无效（点了没反应）          [a545ab49] 已删滑条
    位置：shaders/lib/post/GradeCore.glsl（POTATO_GAMMA_APPROX 恒定义 ⇒ gamma 走 sqrt）
    做法：两选一：① `#if GAMMA_CORRECTION != 2.0` 时回落 pow（让滑条真的能用）；
          ② 直接删滑条
    收益：无（是清掉一个空旋钮）
    风险：低；①会改变非 2.0 设定下的画面，需你决定

五、P3：结构性大改（按收益排序）
--------------------------------------------------------------------------------
[ ] P3-1 = C1  SSR 追踪搬到半分辨率 compute + 命中缓冲 + 双边上采样
    收益：0.4–1.5 ms/帧（唯一 ms 级项目）
    成本：2–4 天；可复用现成范式（ReprojectScene / UpscaleDiffuseIndirectFrom）
    风险：高 —— 本仓有两次「半分辨率 imageStore 读不到」的前科
    做法要求：先做「只写调试色」的最小验证链路，确认读写通再搬逻辑
    观感：半分辨率追踪+双边上采样，边缘可能有轻微软化 ⇒ 需要对比图

[ ] P3-2 = C2  G-buffer 带宽收窄
    做法：colortex8 RGBA16_SNORM -> 8bit；colortex7（RGBA16UI 打包）改位域压缩
    收益：G-buffer 写带宽 -20%（≈90 MB/帧）
    风险：高（牵连全链；法线 8bit 会有色带，需要重新映射/量化）
    条件：实机确认当前是带宽瓶颈再动

[ ] P3-3 = C3  DOF 不再把整张场景色复制进 colortex3
    做法：Prepare 只写 CoC，Gather 直接读 colortex0、写 colortex3
    收益：16.6 MB/帧（跨 4 个 pass 改道）
    风险：中（DOF 关闭时拷贝也要能省掉）

[ ] P3-4 = C5  雾噪声二八度烘成 128³ R8 3D 纹理
    收益：12.4M -> 6.2M 采样/帧（0.05–0.12 ms）
    成本：半天；风险：低（只是换数据来源）
    注意：会多占 2MB 显存

[ ] P3-5 = C4  bloom 横纵两趟合并成单 pass LDS
    收益：0.03–0.06 ms/帧
    成本：工作量 L（要重写两份 bloom kernel）
